# Файл контекста

Пакет про файл, который **читается первым и целиком, каждую сессию**. Из этого
следует всё остальное: место в нём дорогое, порядок блоков имеет значение, а
неверная формулировка не просто не помогает — она уводит, и уводит каждый раз.

Два листа: как устроен файл и как в нём описан стек. Второй вынесен отдельно
потому, что ошибаются там одинаково и предсказуемо — пишут опись того, что
есть, вместо того, что должно быть.

## Правила

Каждый пункт действует сам по себе. За причиной, примерами и проверкой
открывается лист.

### Устройство файла → [structure.md](structure.md)

- **Терминология — одним из первых блоков.** Инструмент, не знающий терминов,
  переспрашивает или угадывает, и угадывает мимо.
- **Адресаты разделены:** правила для людей, правила для инструментов и
  справочные сведения — разные вещи и живут раздельно.
- **Инвариант называется вместе с местом проверки.** Инвариант без места
  проверки не выполняется.
- **Запреты нумеруются** — на запрет с кодом можно сослаться и его можно
  проверить.
- **Условия загрузки скиллов перечислены в файле, и по всем скиллам:** скилл
  не появляется в работе сам.
- **Файл остаётся загружаемым.** Правила в конце длинного файла весят меньше,
  чем в начале, — это свойство чтения, а не небрежность.
- **Язык один.** Файл наполовину на русском, наполовину на английском читается
  хуже любого из двух.

### Раздел стека → [target-stack.md](target-stack.md)

- **Стек описывается как целевое состояние, а не как опись текущего.** Иначе
  новый код воспроизводит легаси, ссылаясь на этот же файл.
- **У каждого выбора названа причина.** Список названий без причин не помогает
  принять следующее решение.
- **Пересмотр привязан к названным поводам,** а не к пожеланию «когда-нибудь
  пересмотрим».
- **Целевое не значит новейшее.** Выход новой версии сам по себе не основание.
- **Новая зависимость — тоже решение по стеку** и проходит через те же
  вопросы.

## Смежное

- `architecture-placement` — оси раскладки и границы, которые этот файл
  называет.
- `docs-decisions` — куда уходит подробная причина выбора.
- `quality-review` — сверка кода с тем, что здесь записано.
