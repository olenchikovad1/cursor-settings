# Имена в коде

## Разделение ролей

**Имена — на английском. Комментарии и docstring — на русском.** И на бэкенде, и
на фронтенде.

Это не компромисс, а разделение по адресату. Имя живёт внутри синтаксиса языка,
его читают и человек, и инструмент, оно уходит в API, в базу, в логи.
Объяснение читает только человек, и ему нужен родной язык.

Смешение калечит обе стороны. Русские идентификаторы ломаются на границах — в
URL, в именах колонок, в чужих библиотеках, в кодировках. Английские комментарии
пишутся беднее, чем думается, и объясняют меньше, чем могли бы.

## Имя отражает смысл, а не тип и не происхождение

`data`, `result`, `tmp`, `obj`, `item2`, `manager`, `helper`, `utils` не
сообщают ничего.

Хорошее имя отвечает на вопрос «что это в предметной области». По нему видно,
что вернёт функция и что хранит переменная, без чтения тела.

Отдельно про множественное число и логические значения: `orders` — список,
`order` — один, `is_paid` — да или нет. Мелочь, которая экономит чтение
каждый раз.

## Как выглядит

**Неправильно:**

```python
def process(obj, f=False):
    data = get(obj.id)
    tmp = [x for x in data if x.f]
    return tmp
```

**Правильно:**

```python
def reserve_stock(order: Order, allow_partial: bool = False) -> Reservation:
    items = order_items.for_order(order.id)
    unavailable = [item for item in items if not item.is_in_stock]
    ...
```

Имя `process` не отвечает ни на один вопрос вызывающего: что произойдёт с
объектом, что вернётся, можно ли звать дважды.

## Проверка, которая всегда работает

**Если рядом с именем нужен комментарий, объясняющий, что это, — имя выбрано
неудачно.**

Комментарий должен объяснять «зачем» и «почему так», а не «что это». Как только
он начинает объяснять «что», сначала чинится имя.

## Имя — документация, которая не устаревает

Комментарий можно забыть поправить при изменении поведения. Имя приходится
менять вместе с кодом — компилятор или тесты заставят.

Отсюда практический вывод: **вкладываться в имя выгоднее, чем в комментарий**.
При равном усилии имя проживёт дольше и соврёт реже.

## Коды состояний и ошибок

Латиницей в верхнем регистре: `ORDER_ALREADY_SHIPPED`, `PAYMENT_DECLINED`.

Они попадают в API, в базу и в реестры, их читают клиенты. **Переименование
такого кода — ломающее изменение**, поэтому имя выбирается по смыслу отказа, а
не по месту в коде: `SHIPPING_SERVICE_ERROR_42` переживёт первый же рефакторинг
и станет ложью.

## Английские слова в русском тексте — норма

Термины, имена классов, переменных, таблиц, кодов не переводятся:
`PublicationOutbox`, `idempotency key`, `readback`.

Правило про язык относится к **связному тексту**, а не к вкраплениям.

- Правильно: «Гейт `PUBLISHING_BLOCKED` проверяется в transport guard».
- Неправильно: «Гейт блокировки публикации проверяется в транспортном стороже» —
  ни одного из этих слов в коде не существует, и читатель не найдёт то, о чём
  прочитал.
