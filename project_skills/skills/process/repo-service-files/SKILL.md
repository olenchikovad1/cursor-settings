# Служебные файлы репозитория

## Они складываются сами, и это плохо

Список скрываемого дописывается по строке — обычно после того, как лишнее уже
попало в историю. Поведение с переводами строк не задано вовсе. Стратегия
отправки у каждого своя.

Каждый из этих файлов действует **на всех, кто клонирует репозиторий**, и
чинится один раз. Поэтому здесь действует исключение из общей границы объёма
(`quality-review`): служебный файл, оформленный неправильно,
приводится в порядок сразу, а не записывается находкой на потом.

## Что скрывается — по признаку, а не списком расширений

Список устаревает с каждым новым инструментом; признак — нет.

Скрывается:

- **порождённое сборкой** — всё, что воссоздаётся из исходников: каталоги
  сборки, скомпилированное, кэши;
- **локальное для машины** — виртуальные окружения, установленные зависимости,
  временные файлы;
- **личное для среды разработки** — настройки редактора конкретного человека;
- **всё, что содержит секреты** — файлы окружения, ключи, сертификаты. Рядом
  кладётся **образец** без значений, чтобы было видно, что вообще требуется.

Не скрывается: файл фиксации версий зависимостей — он часть воспроизводимости
сборки (`architecture-dependencies`).

Отдельный вопрос — общие настройки среды разработки. Часть из них полезна всем
(единый форматтер, кодировка); они в репозитории. Личные — нет. Смешивать
нельзя: личное, положенное в репозиторий, начинает навязываться.

### Базовый список, который есть всегда

Признак не отменяет того, что часть позиций одинакова во всех проектах и
пишется сразу, а не после того, как лишнее попало в историю:

- **среды разработки** — каталоги настроек всех, кем в проекте пользуются
  (`.idea/`, `.vscode/`), а не только своей. Человек с другим редактором придёт
  позже, и его файлы попадут в историю ровно один раз, зато навсегда;
- **порождённое языком** — кэши байт-кода (`__pycache__/`, `*.pyc`), каталоги
  сборки и упаковки, результаты компиляции;
- **окружения и зависимости на месте** — виртуальные окружения,
  `node_modules/`;
- **кэши инструментов** — проверок типов, линтеров, тестов, покрытия;
- **временное и системное** — файлы, которые создаёт операционная система при
  просмотре каталогов, файлы редакторов, журналы;
- **файлы окружения со значениями** — при этом образец без значений остаётся.

Список пишется **при создании репозитория**, а не пополняется по одной строке
после каждого промаха: каждая такая строка означает, что что-то уже попало в
историю и его пришлось снимать с наблюдения.

## Скрытие задним числом ничего не убирает

Файл, однажды взятый под наблюдение, продолжает отслеживаться, сколько его ни
добавляй в список. Его надо **снять с наблюдения** отдельным действием, и это
изменение видно всем.

Если это был **секрет** — правил недостаточно. Файл остаётся в истории
навсегда, и секрет **отзывается**, а не удаляется (`quality-security`).
Переписывание истории ради его удаления — отдельное дорогое решение, которое
почти никогда не оправдано: отозвать дешевле.

## Переводы строк задаются в репозитории

Не настройками на машинах: настройка у каждого своя, и один и тот же файл
выглядит изменённым у половины команды.

Последствия хуже, чем кажется: разбор истории тонет в шуме, слияния дают
конфликты во всём файле, а поиск виновника изменения перестаёт работать.

Задаётся: поведение по умолчанию для текстовых файлов и явные исключения для
тех, кому перевод менять нельзя, — исполняемые сценарии оболочки, файлы с
фиксированным форматом.

Изменение этого поведения один раз перетряхивает всё дерево. Делается
**отдельным изменением**, не вместе с работой по задаче: иначе в этом коммите
не найти ничего.

## Двоичное не сливается построчно

Файлы, которые нельзя слить построчно, помечаются как двоичные: изображения,
архивы, документы офисных форматов, скомпилированное.

Попытка слить такой файл построчно портит его **молча** — он остаётся на месте
и перестаёт открываться. Замечают позже, обычно не сразу поняв причину.

Заодно помечается то, что не нужно показывать в разборе изменений: сгенерённый
код, файлы фиксации версий. Их разбор длиной в тысячи строк прячет настоящие
изменения.

## Стратегия отправки задана явно

Умолчание, при котором одна команда отправляет больше веток, чем человек имел в
виду, — это изменения в общей ветке, которых **никто не делал сознательно**.

Выбор описывается словами:

- **только текущую ветку, в ветку того же имени** — годится почти всегда, и это
  разумное умолчание для проекта;
- **только текущую, в связанную с ней** — когда имена веток локально и на
  сервере намеренно расходятся;
- **все совпадающие ветки** — почти никогда: одна команда трогает то, о чём в
  этот момент не думают.

Отдельно решается, создаётся ли связь с веткой сервера автоматически при первой
отправке: без этого каждая новая ветка требует лишнего ключа, с этим — ветка
уезжает на сервер, возможно раньше, чем её собирались показывать.

## Что общее, а что личное

**В репозитории** — то, что должно действовать на всех: список скрываемого,
поведение с переводами строк, пометки двоичных файлов, общий формат.

**У человека** — имя и почта автора, ключи подписи, предпочитаемый редактор,
сокращения команд.

Личное, положенное в репозиторий, навязывается остальным. Общее, оставленное
личным, не действует ни на кого — и обнаруживается это в момент, когда кто-то
новый клонирует репозиторий.

## Проверка

- клонировать репозиторий на машине с другой операционной системой — состояние
  сразу чистое, изменённых файлов нет;
- собрать проект — ничего порождённого сборкой в изменениях не появилось;
- отправить одну ветку — уходит одна;
- посмотреть, отслеживается ли что-то из того, что должно быть скрыто, — нет;
- открыть разбор изменений с двоичным файлом — он не показан построчно.

## Чего не делать

- дописывать список скрываемого по одной строке после каждого промаха;
- считать, что добавление в список убирает файл из истории;
- удалять попавший в историю секрет вместо того, чтобы его отозвать;
- задавать переводы строк настройками на машинах;
- менять поведение с переводами строк вместе с работой по задаче;
- оставлять стратегию отправки на умолчание.

## Смежное

- `process-git` — что происходит при отправке в общую ветку.
- `quality-security` — секреты в истории и почему их отзывают.
- `architecture-dependencies` — почему файл фиксации версий не скрывается.
- `ops-containers` — у сборки образа свой список исключений, и он другой.
