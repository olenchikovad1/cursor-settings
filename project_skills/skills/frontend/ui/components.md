# Библиотека компонентов

## Признак, что скилл нужен

Приходится говорить «сделай сортировку в столбцах как в той таблице».

Эта фраза означает ровно одно: **общего компонента нет**. Каждая таблица
делается заново, и пользователь на соседних экранах получает разное поведение
одного и того же элемента.

## Поведение по умолчанию задаётся один раз

Таблица умеет сортировку, фильтрацию и пустое состояние **сама**, без отдельной
просьбы. То же для формы, списка, диалога, выбора значения.

Разница принципиальная. Если поведение — опция, оно будет включено на трёх
экранах из десяти, и на остальных семи пользователь решит, что оно сломалось.
Если поведение по умолчанию — его нужно осознанно выключать, и это заметно на
ревью.

Что обычно должно быть по умолчанию:

- **таблица** — сортировка по колонкам, пустое состояние, состояние загрузки,
  сохранение выбранной сортировки при возврате на экран;
- **список** — пустое состояние, ошибка загрузки, догрузка или пагинация;
- **форма** — показ ошибок полей, блокировка повторной отправки, сохранение
  введённого при отказе сервера;
- **диалог** — закрытие по клавише, возврат фокуса туда, откуда открыли.

## Порядок при новой задаче

Тот же, что в `architecture-placement`:

1. посмотреть библиотеку компонентов;
2. посмотреть соседние экраны, решающие похожую задачу;
3. взять ближайшее по смыслу.

Ничего нет — создать **в общем месте** и переиспользовать дальше. Компонент,
созданный рядом с экраном «пока здесь», остаётся там навсегда.

## Правишь существующий экран — выноси то, что уже повторяется

Порядок выше — про новую задачу, и этого мало: дубли появляются не при создании
экрана, а при его правке. Открыл экран, увидел рядом рукописный блок — галочки
выбора строк, панель действий над выбранным, набор чекбоксов, строку фильтров, —
**не достраивай по образцу**. Посмотри, есть ли этот блок на другом экране; есть
— выноси в набор сейчас, вместе со своей правкой.

Почему именно сейчас, а не «отдельной задачей». Достроенный по образцу блок
выглядит уместным: он такой же, как соседний. Через правку он расходится с ним на
одну деталь, ещё через одну — на три, и к моменту, когда дубль замечают, их уже
не два, а шесть, и каждый ведёт себя по-своему.

Признак, по которому это видно без раздумий: **один и тот же блок разметки второй
раз**. Не «похожий» — тот же по смыслу: то же действие, тот же вид, те же
состояния.

Что почти всегда стоит вынести, потому что повторяется в любом проекте:

- таблица со списком и её состояния;
- выбор строк галочками и панель действий над выбранным (включая «галочка в
  шапке выбирает найденное, а не весь список»);
- строка фильтров над таблицей;
- набор признаков галочками, в том числе с третьим состоянием «есть у части
  выбранных»;
- выбор одной сущности с поиском;
- диалог правки одной строки.

## Расширять, а не копировать

Компонент почти подходит — добавляется параметр. Копия «как тот, но чуть иначе»
и есть механизм расхождения.

Граница: если параметры стали взаимоисключающими и их больше двух-трёх — внутри
живут два разных компонента, и их пора разделить.

## Поведение списка выключается только с записанной причиной

Общая таблица даёт постраничность, сортировку, пустое состояние и состояние загрузки
**по умолчанию**. Значит выключение — это решение, и его надо обосновать там же, где
оно сделано:

```tsx
// Постраничность выключена осознанно: строки одного документа — их столько,
// сколько набрали, и раскрыты они внутри его строки.
pagination="off"
```

Почему именно так. `pagination="off"` пишется одной строкой и выглядит невинно, а
означает «на этом экране страниц не будет никогда». Живой пример: девять списков подряд оказались без страниц, потому что строку
выключения скопировали с соседнего экрана; каждый из них растёт, и на каждом человек
рано или поздно упирался в обрезанный список без объяснения. Причина рядом с выключением превращает
следующую такую правку в осознанный выбор, а не в копирование строки с соседнего
экрана.

Признак, по которому решается: **список растёт со временем** — постраничность
нужна. Перечень ограничен самим предметом (строки одного документа, состав одного
комплекта, упаковки одного SKU) — выключение законно, и причина именно в этом.

Машинная часть: проверка ищет выключение, у которого в нескольких строках выше нет
объяснения, и сообщает о нём.

## Форма, разложенная по столбцам, — та же таблица

Соблазн выглядит так: «здесь не список, а форма — ячейки хранят несохранённый ввод,
добавление и удаление строк это часть ввода, значит общий компонент не подходит».
Звучит убедительно и один раз уже было записано как законное исключение.

Чем это кончилось: под исключение уехали восемь рукописных таблиц — состав черновика,
строки задания, набранные комплекты, решения по единицам возврата, разбор файла импорта,
справка по колонкам шаблона. Каждая разошлась с остальными: у одной своё поле количества
со своим шагом, у другой свои отступы и своя шапка, у третьей потерялось пустое
состояние, у четвёртой кнопка «убрать» другого вида. Ровно то расхождение, ради
предотвращения которого набор и существует.

Правило: **любая таблица идёт через общий компонент**, поля ввода живут в её ячейках.
Столбцу, который не сортируется, ставится `sortable: false`; постраничность выключается
с записанной причиной (см. раздел выше). Ничего больше для формы не нужно.

Признак, что правило пытаются обойти: в файле экрана появился тег `<table>`. Машинную
часть держит проверка границы компонентов — она такой тег отбивает.

## Проверка

Открыть два экрана со списками и сравнить поведение при сортировке, при пустом
результате и при ошибке. Отличается — правило нарушено.

Вторая проверка — по diff своей правки: если в ней появилась разметка, которая уже
есть на другом экране, правило нарушено независимо от того, как выглядит результат.
Машинную часть держит хук `guard_ui_boundary.py`: после каждой правки он называет
рукописные блоки, для которых в наборе есть компонент, импорт сторонней библиотеки
вне набора и выключенную без причины постраничность. Это предупреждение, а не
отказ — правка уже сделана, чинится в том же ходу. Перед слиянием то же проверяется
по всему дереву: `py -X utf8 .cursor/hooks/guard_ui_boundary.py --scan`. Раскладка —
ключи `frontend_src`, `ui_set_dir`, `ui_root_dir`, `component_libraries` в `rails.json`.

Это видно снаружи и не требует чтения кода, поэтому проверять может кто угодно.
