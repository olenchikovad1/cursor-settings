# Контекст проекта resume

Интерактивное резюме: содержание можно прочитать, устройство — посмотреть.
Заменяет собой не документ с площадки (формальная версия остаётся там), а то,
чего в формат резюме не влезает: опыт вкладками, навыки панелями, живой
авторский текст.

Стек и его обоснования — в самом репозитории: стек называется в `CLAUDE.md`,
обоснования лежат в файле архитектурных решений. Здесь их дублировать нельзя,
копии расходятся.

## Путь на этой машине

`path_expr`, а не `remote`: у проекта нет удалённого репозитория и **не будет
второй машины**. Публичный репозиторий автор создаёт сам, когда сочтёт проект
готовым; после этого сюда добавится `remote`, а `path_expr` останется.

## Особенности

- **Первый коммит — только с работающим фундаментом.** Решение автора: пока
  приложение не запускается, коммитов в репозитории нет вообще, чтобы в истории
  не осталось нерабочих состояний. До этого момента работа идёт прямо в
  `master`, без ветки задачи. После первого коммита — обычные ветки `feat/*`.
- **Рабочее окружение вне git.** `.claude/`, `CLAUDE.md`, `docs/` и
  `readme_legacy.md` скрыты через `.git/info/exclude` — файл внутри `.git`,
  который не коммитится и в клон не попадает. Причина не техническая:
  в репозитории не должно быть следов того, чем автор пользуется при
  разработке.
- **`readme_legacy.md` заморожен.** Исходный readme проекта, переименованный
  и больше ничем не тронутый. Не правится и не сокращается; удаляется только
  по прямому решению автора, когда всё его содержимое переедет в другие места.
- **Всё запускается только в докере.** Ни Python, ни Node на машине нет,
  и ставить их не нужно. Тесты фронтенда идут в отдельном сервисе
  `web-test` (профиль `test`, стадия `deps`): рабочий образ `web` — это
  nginx, и `npm` в нём отвечает «not found».
- **Быстрый контур бэкенда** — `pytest -q`: тесты с базой отсекаются
  маркером и в цикле не идут. Полный — `pytest -q -m db` один раз
  на блок работы.
