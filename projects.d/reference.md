# Контекст проекта reference

«Референс» — работа с принтами: от «вот интересная картинка» до файла на
фабрику. Приложение платформы, код `reference`, живёт под `/reference/`.

**Стек** взят у платформы целиком: FastAPI + SQLAlchemy 2.x async + Alembic +
Pydantic v2 + PostgreSQL 17 (бэкенд), React 19 + Vite + TypeScript + Tailwind 4
+ Radix через пакеты `@platform/*` (фронтенд). Всё в докере.

**Раскладка сервиса:** слои снаружи (`models`, `schemas`, `repositories`,
`services`, `api`, `consumers`, `schedulers`), файл на домен внутри. Пакет —
`api/reference_api/`, фронтенд — `web/`.

**Ветка задачи не создаётся.** Работа идёт прямо в `master`: репозиторий
односессионный, ревью не бывает, всё восстанавливается по истории. Отступление
записано в `docs/decisions/0007-work-goes-straight-to-master.md` и в самом
правиле `.claude/skills/process-git/SKILL.md`. Поэтому `branch_prefix: null` —
это не пропуск, а решение.

**Удалённого репозитория пока нет**, пушить некуда. Из этого следует
неочевидное: резолвер сличает клоны по `git remote get-url origin`, и без
`origin` обход корней проект НЕ находит. Путь приходится задавать руками на
каждой машине — `resolve_project.py --register reference <path>`, потому что
`local.json` машинный и в git не уезжает. Появится удалённый — строка
`remote:` заполняется, и регистрация станет не нужна.

**Сборка фронтенда требует запущенного стенда платформы:** пакеты `@platform/*`
ставятся из её Verdaccio через `host.docker.internal:4873`. Если compose
платформы остановлен, `npm install` не пройдёт.

**Стенд:** `docker compose -f infra/compose.yaml up -d --build`, порты — сервис
8010, фронтенд 5183, PostgreSQL 5433, MinIO 9010/9011, RabbitMQ 5673/15673.

**Тяжёлые файлы вне git.** Исходники изделий (`.bw` из Browzwear, сотни
мегабайт) лежат в томе `infra/stand/files/`, в репозитории — только описание с
хешами.

## Серверы

Обход 24.09.2026, подробности — `plans/notes/065-hosts.md`. Адреса, порты и
учётные записи здесь не повторяются: они в файле доступов на машине.

**hub, полный доступ.** Разворачивается там же, где платформа, и её же
средствами.

**Отдельного домена не будет.** Ядро проекта целиком в докере, а наружу он
выходит через шлюз платформы — маршрут заводится внутри `platform-gateway`, а
не записью в системном nginx. Прав администратора хоста для этого не требуется:
членство в группе `docker` есть.

**На 24.09.2026 на hub его ещё нет** — ни виртуального хоста, ни контейнеров.
Запись описывает, куда он поедет.

**Соседи на hub.** `sellerhub`, `t-logistix` и `ts-corp` — чужие приложения; их
не задевать.

## Почему граница по соседям живёт здесь, а не в правах

Правила доступа сопоставляются с началом команды. Всё, что идёт на хост, идёт
одной строкой `ssh …`, и что внутри неё — правилу не видно: «перечитать свой
блок веб-сервера» и «переложить чужое приложение» для него одинаковы.

Значит граница по соседям **не выражается правами и держится этой записью**.
Права закрывают только то, что видно по началу команды: снос томов, удаление
базы, силовой пуш в базовую ветку проекта, миграции — вопросом.

Соседи по хостам названы выше поимённо. Их порты, домены, каталоги и службы не
задеваются ни при каких условиях; читать их конфигурации можно.
