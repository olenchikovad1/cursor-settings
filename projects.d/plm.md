# Контекст проекта plm

**Копия PLM-портала, а не боевой портал.** Полная копия `plmportal` от
22.09.2026. Боевой портал живёт своей жизнью в своём репозитории, и ничего
из сделанного здесь его не касается. Переписывание идёт в четыре шага:
привести к целевому стеку, вычистить наследие, накатить сделанное в боевом
после снятия копии, перевести людей.

Устройство, инварианты и запреты — в `CLAUDE.md` репозитория. Решения —
`docs/decisions/`. Правила разработки — 28 правил в `.claude/skills/`.

## Чем отличается от `plmportal`

- **Ломать можно и нужно:** у копии нет пользователей. Неработающий экран
  и красный тест — не происшествие.
- **Переход не поэкранный, а целиком:** Next.js и Prisma заменяются на
  React + Vite и FastAPI + SQLAlchemy, переходных слоёв и двойной записи
  не заводится.
- **Своего боевого контура нет.** `/ship`, `/status`, `/logs` нацелены на
  чужой и здесь не запускаются. Пуш в `master` разрешён владельцем
  23.09.2026 на время переписывания.
- **База одна и своя:** в неё ложится и пришедшее из Cosmic, и заведённое
  у нас. Боевой `plmportal` — образец вида, а не источник кода.
- **Вход только через платформу.** Ни своей формы входа, ни таблицы
  пользователей, ни ролей, ни раздела «Учётные записи» — раздел снят
  23.09.2026.

## Стенд

Два контейнера: `plm-api` (uvicorn, FastAPI, Python 3.13) и `plm-db`
(PostgreSQL 17.2, порт 5439). Приложение живёт за шлюзом **локальной**
платформы на `http://localhost:8100/plm/`; вход — платформенный.

Описание приложения платформе публикуется отдельным шагом и **только
с пересборкой**: `docker compose run` образ не пересобирает, и без `--build`
уезжает вчерашний состав разделов.

```
docker compose --env-file infra/.env -f infra/compose.yaml --profile publish run --rm --build publish
```

## Особенности

- **Пакеты платформы берутся из её боевого реестра** (`.npmrc`, решение
  0008). Выпущенное в локальный реестр рядом стоящей платформы сюда не
  приезжает: до 23.09.2026 выкладка пакетов на сервер делалась руками по
  абзацу из `deploy/README.md`, сейчас платформа переносит её внутрь выкатки.
- **Трейлеры соавторства в коммитах запрещены** (правило `process-git`).
- **Компонент берётся у платформы**, недостающее — в `frontend/src/kit/`,
  и каждый такой файл считается заявкой платформе. На странице компонент
  не пишется никогда.
- **Секреты лежат в репозитории открыто** и это норма до первого живого
  человека на своём боевом (допущение Д-1): репозиторий закрытый.

можно.

## Почему граница по соседям живёт здесь, а не в правах

Правила доступа сопоставляются с началом команды. Всё, что идёт на хост, идёт
одной строкой `ssh …`, и что внутри неё — правилу не видно: «перечитать свой
блок веб-сервера» и «переложить чужое приложение» для него одинаковы.

Значит граница по соседям **не выражается правами и держится этой записью**.
Права закрывают только то, что видно по началу команды: снос томов, удаление
базы, силовой пуш в базовую ветку проекта, миграции — вопросом.

Соседи по хостам названы выше поимённо. Их порты, домены, каталоги и службы не
задеваются ни при каких условиях; читать их конфигурации можно.
