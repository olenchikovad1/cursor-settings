# Контекст проекта tori-content-factory

Конвейер производства и публикации контента для TORI BRANDS (бренд LARETTO).
Notion — операционный учёт, Telegram — интерфейс управления, публикация закрыта
флагом `publishing_enabled=false`.

Полный контекст приложения — `CLAUDE.md` в самом репозитории: терминология,
границы ответственности, стек, раскладка, технические инварианты. Правила
разработки — 14 скиллов в `.claude/skills/`. Организационные правила (кто кого
согласовывает) — в `AGENTS.md`, к разработке отношения не имеют.

## Стек

Python 3.13+ / FastAPI / SQLAlchemy 2.x / Alembic / PostgreSQL, зависимости
через **uv** (`pyproject.toml` + `uv.lock`). Отдельный Node-подпроект Remotion
для рендера видео. Фронтенда пока нет — два серверных HTML-шаблона, которые по
плану 018 заменяются на React.

## Тесты

```
uv run pytest -q -rs
```

`-rs` обязателен: часть тестов пропускается вне боевого сервера, причины
пропуска нужно видеть. Ожидаемо на 03.09.2026: **529 проходят, 11 пропущены**.

Пропуски двух видов, оба осознанные: POSIX-специфичные механизмы на Windows
(режимы доступа файла, `replace` поверх открытого дескриптора, `fsync`
каталога, shebang — см. `tests/posix_only.py`) и тесты, которым нужны файлы
сервера, отсутствующие в репозитории.

**База данных в тестах — PostgreSQL**, SQLite в проекте не используется. Каждая
созданная тестом сущность получает префикс `DEMO-` и удаляется после прогона.
На 03.09.2026 это ещё не реализовано — этап 3 плана 018.

## Особенности этой машины (RBB-0001)

`uv` установлен через `py -m pip install uv`, и каталог `Scripts` интерпретатора
**не на PATH**. Поэтому здесь команды выполняются как `py -m uv run pytest`, а
не `uv run pytest`. В реестре записана каноническая форма — на машине с uv на
PATH она работает как есть.

Docker Desktop, Node и npm на месте.

## Ветки и коммиты

Рабочая ветка — **`develop`**, коммиты идут в неё напрямую логическими блоками.
Это решение пользователя на время закладки фундамента: изменения должны быть
видны одной линией истории, потому что дальше по этому коду будут работать люди,
слабо знакомые с проектом.

`git push` **не выполняется** без явного разрешения — разрешения нет.

Единого `branch_prefix` нет: имя ветки начинается с типа изменения
(`feat/`, `fix/`, `refactor/`, `test/`, `docs/`, `chore/`, `deploy/`), тот же
тип идёт в заголовок коммита через двоеточие. Служебные подписи в теле коммита
(`Co-Authored-By` и подобные) запрещены. Подробности — скилл `git-workflow` в
репозитории.
