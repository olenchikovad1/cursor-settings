# cursor-home

`~/.cursor` — общее пространство двух машин (дом и офис) для работы в Cursor:
скиллы, библиотека правил для проектов, хуки, разрешения, реестр проектов,
эталоны времени, планы. Синхронизируется через приватный GitHub
`olenchikovad1/cursor-settings`. Рядом живёт `~/.claude` — то же самое для
Claude Code; из него берут, в него не пишут.

## Терминология

- **Машина** — дом или офис. Роль лежит в `local.json` (поле `role`), файл
  машинный и в git не входит. Без роли автосинхронизация пушит прямо в `master`.
- **Личная ветка** — `wip/<роль>`. В неё каждый ход уходит катящийся коммит
  сессии; `master` в течение сессии не двигается.
- **План** — файл `plans/NNN-<направление>-<слаг>.md`. Нумерация своя, с 001
  (01.10.2026). Актуальные планы Claude перенесены под новыми номерами, в шапке
  у них `migrated_from: "claude/NNN"`; остальное в `~/.claude/plans/` — архив,
  в счёт номеров не идёт и калибровкой не читается. Истории перенесённых
  планов сохранили прежние номера, новые истории — с `US-0001`.
- **Манифест проекта** — `projects.d/<имя>.md`: remote, базовая ветка, команды
  тестов, флаги. Общий для машин. Путь на этой машине — в `local.json`.
- **Библиотека** — `project_skills/`: правила, которые ставятся в проекты
  (`.cursor/skills` + хуки + `rails.json`), а не действуют отсюда.
- **Версия эталонов** — граница, с которой время считается по-новому;
  `references/versions.json`. Действующая — 3, «переход на курсор».

## Устройство

| Что | Где | В git |
|---|---|---|
| Контекст (этот файл) | `AGENTS.md` | да |
| Личные скиллы | `skills/` | да |
| Библиотека для проектов | `project_skills/` (`install.py`, `validate.py`, `README.md`) | да |
| Хуки и их настройка | `hooks/`, `hooks.json` | да |
| Разрешения на команды | `permissions.json` | да |
| Реестр проектов | `projects.d/`, резолвер `hooks/resolve_project.py` | да |
| Эталоны и калибровка | `references/`, `time-analysis/` | код — в `master`; `matrix.json` и `records/` — ветка `calibration` |
| Планы | `plans/` | да |
| Пути на этой машине, роль | `local.json` (образец `local.example.json`) | **нет** |
| SSH-хосты и логины | `infra_ssh_hosts.md` | **нет**, приносится руками |
| Чаты, кэш приложения, расширения | `projects/`, `skills-cursor/`, `extensions/`, `plugins/` | нет |

Кто за что отвечает в `hooks.json`:

- `guard_destructive.py` — запрещает снос томов, `rm -rf` от корня, силовой
  пуш в базовые ветки; миграции — вопросом.
- `time_estimate.py` — замеряет ходы и напоминает про строку с оценкой.
- `guard_plan_in_progress.py` — на `stop` не даёт бросить план
  `in-progress`: `followup_message` до конца незакрытых историй
  (`loop_limit: 400`). Заявка — `plan_session.py --claim`. Правило —
  `execute-plan` / `continuity.md` и `rules/plan-end-to-end.mdc`.
- `autosync_cursor.py` — коммит в `wip/<роль>` на каждом ходу, `master` на
  границе сессии. `--status`, `--show-wip`, `--adopt-wip`, `--drop-wip --yes`.
- `compact_hint.py` — подсказка перед сжатием; при активном плане ещё и
  `additional_context` модели «сжатие не пауза — продолжай план».

## Инварианты

1. **Работа идёт прямо в `master`, без ветки задачи.** Репозиторий
   односессионный, ревью нет, ветка мешала бы автопушу. Исключение из правила
   `execute-plan`.
2. **`~/.claude` только читается.** Claude Code продолжает работать, его данные
   ничем не правятся. Перенос — копия с перенастройкой путей на `~/.cursor`.
3. **Личные разрешения шире проектных.** `permissions.json` здесь — для
   владельца; в проекты ставится `project_skills/permissions.project.json`,
   где пуш, коммит, установки и миграции подтверждаются мышкой.
4. **Секреты и машинное не уезжают в git.** Проверяется `.gitignore`; перед
   добавлением нового файла в синхронизацию — посмотреть, нет ли в нём адресов
   и учёток.
5. **Размер истории записывается до работы, факт — после.** Держится
   `time-analysis/calibrate.py story-start` / `story-close`.

## Запреты

1. **Не пушить `master` силой** и не чинить расхождение машин переписыванием
   истории: сначала `--show-wip`, потом `--adopt-wip` или `--drop-wip`.
2. **Не дописывать `rolling_commits` и `wip_branches` в чужие манифесты** —
   эти флаги законны только у `cursor-home` и `claude-home`.
3. **Не копировать `infra_ssh_hosts.md` никуда**, кроме второй машины руками.
4. **Не править `~/.claude`.**

## Когда какой скилл открывать

- дали задачу или пачку задач → `write-plan`
- «приступай к плану N» → `execute-plan`
- сменил машину, вернулся после обрыва, «на чём остановились» → `resume-work`
- планы или настройки не доехали между машинами, git в `~/.cursor`
  конфликтует, правлю `hooks.json` → `distributed-setup` (лист `cursor-sync.md`)
- собираюсь назвать срок шага или задачи → `progress-time-estimates`
- ставлю размер, завожу эталон, «заводим новую версию» → `time-estimate-calibration`
- просят поставить правила в проект, «подтяни скилы» → `install-project-skills`
- пишу или правлю скилл → `write-skill`
- собираюсь сказать «готово» → `quality-verification`
- выдаю владельцу команду для ручного запуска, нужен ssh или sudo →
  `owner-runnable-commands`, адреса в `infra_ssh_hosts.md`

## Технологии

Python через `py -X utf8`, без внешних зависимостей: хуки и калибровка должны
запускаться на голой машине сразу после клонирования. Тесты —
`hooks/tests/`, `project_skills/hooks/tests/`, `time-analysis/test_*.py`;
для остального критерий «готово» — построчная сверка с планом.

Особенности этой среды: `python` без `py` не работает; часть команд падает
с «Terminal unavailable … sandbox» — такие запускаются через
`py -X utf8 -c "subprocess.run([...])"`; `gh` не установлен; кириллица в
выводе PowerShell ломается при фильтрации — читать через файл.
