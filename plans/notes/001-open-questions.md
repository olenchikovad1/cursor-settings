# 077 — открытые вопросы

## US-0525. Пятисотая при быстрых кликах не воспроизвелась

Руководитель на встрече 25.09.2026 получил «Ошибка сервера. Проверьте, что API и
Postgres запущены» на справочниках товарных групп и производителей. Этот текст
кабинет ставит только на настоящий ответ 500.

Что проверено — ни одна проверка 500 не дала:

- 240 одновременных запросов к спискам и счётчикам использования этих справочников
  на дев-стенде — все 200;
- то же на копии боевой базы (12 305 товаров, дамп прода) — все 200 за 1.7 секунды;
- 60 одновременных запросов по настоящему адресу стенда через хостовый nginx и nginx
  контейнера — все 200;
- билеты сокета уведомлений и счётчики уведомлений (их кабинет дёргает на каждом
  переходе) под той же нагрузкой — все 200;
- неверный вид справочника — честный 404;
- блокировок на чтение в пути справочников нет — `FOR UPDATE` стоит только в
  проведении документов.

Почему не установить: логи API за время встречи пропали вместе со старым
контейнером при выкатке, а журналы хостового nginx без sudo не читаются.

Что сделано, чтобы в следующий раз было по чему разбирать:

- `apply.sh` перед каждым подъёмом сохраняет логи `api`, `worker` и `web` в
  `/opt/assemblage-point/logs/` (последние десять подъёмов);
- переполнение пула соединений и недоступность базы отвечают 503 «подождите», а не
  500, и пишутся в лог вместе с адресом запроса;
- кабинет больше не ходит на сервер при каждом переходе (US-0524), то есть сама
  нагрузка от быстрых кликов снята.

**Нужно от вас:** если ошибка повторится — время с точностью до минуты. По нему её
найдёт `zcat /opt/assemblage-point/logs/*-api.log.gz | grep ' 500 '`. Если есть
доступ с sudo к `/var/log/nginx/error.log` на hub — строки за 25.09 около 09:17 МСК
покажут, отдавал ли 500 сам nginx.

## US-0525. Серверный кэш справочников не сделан — осознанно

В плане есть критерий «справочники отдаются без похода в базу на каждый запрос». Я
его не выполнила, решив так по двум причинам.

1. **Нужды нет по измерениям.** 240 одновременных запросов на копии прода — 1.7
   секунды без единой ошибки. Повторные клики одного человека уже снял кэш в браузере
   (US-0524): шесть переключений между двумя справочниками — по одному запросу на
   каждый.
2. **Риск больше пользы.** В справочники пишут не только через их экран: импорт WB
   заводит бренды и категории, сев — записи, склад — классы хранения. Кэш на сервере
   должен сбрасываться на каждом из этих путей. Пропущенный путь дал бы ровно то, что
   запрещает соседний критерий: «сохранил — получил старое».

**Нужно от вас:** согласиться или сказать «делай». Если делать — правильное место
сброса одно, событие сохранения ORM, а не каждая служба по отдельности. Оценка —
около 3 SP.
