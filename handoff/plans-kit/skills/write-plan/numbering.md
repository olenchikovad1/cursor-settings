# Нумерация планов и историй

## Номер плана

`NNN` в имени файла — сквозной **через всю папку планов, а не через планы
этого проекта**. Следующий номер: максимальный `NNN` в `~/.cursor/plans/`
плюс один, независимо от того, к какому проекту относится предыдущий.

Это сказано отдельно, потому что ошибка типичная: номер выбирают, глядя на
планы своего проекта (024, 025) и прибавляя один, а файл чужого плана с тем
же номером лежит рядом. Два живых плана с одним номером — это два файла,
которые в разговоре называют одинаково.

Проверка одной командой перед созданием файла:

```powershell
Get-ChildItem ~/.cursor/plans/[0-9][0-9][0-9]-*.md | Sort-Object Name | Select-Object -Last 1 -ExpandProperty Name
```

## Направление в имени файла

Имя плана — `NNN-<направление>-<слаг>.md`. Направление стоит и полем `epic:`
во frontmatter; это одно и то же, слово «эпик» в тексте историй не
используется намеренно, чтобы не смешивать с чужими трактовками.

Направление задаётся **смыслом, а не репозиторием**: подключение портала к
платформе — работа по платформе, хотя правки лежат в портале.

**В одном плане одно направление.** Работа, надиктованная сразу по двум,
разъезжается на два плана, и об этом говорится вслух при сдаче — иначе
смешанный план невозможно ни оценить, ни закрыть целиком.

**У живых планов номер уникален.** Живой — тот, по которому работа идёт или
ещё пойдёт (`status: draft`, `in-progress`, `paused`). Повтор внутри одного
направления — ошибка всегда, и правится он до начала работы.

Проверяет это `hooks/lint_plan.py`: имя без направления — ошибка.

## Номер истории

`US-NNNN`, четыре цифры, сквозная через все планы. Первая история первого
плана — `US-0001`. Следующий номер — максимальный `US-NNNN` среди планов
`~/.cursor/plans/` плюс один.

**Номера `US-9001`–`US-9999` заняты эталонами** (`references/stories/`) и в
планах не используются. Эталон в тексте истории называется только путём
`references/stories/US-9NNN.md`: голый номер означает историю этого же плана.

Если номера совпали — это исправляется перенумерованием до начала работы,
пока замена стоит одну команду. После начала работы номер уже лежит в
журнале фактов, и трогать его дороже: тогда живут оба, а различать истории
помогают заголовок и боль рядом с номером.

## Проверка

- перед созданием файла выполнить команду поиска максимального номера — файл
  назван следующим за ним;
- найти в папке два живых плана с одним номером — таких нет;
- открыть последний по номеру план и сверить максимальный `US-NNNN` с новым —
  не пересекаются.

## Чего не делать

- выбирать номер плана, глядя на планы своего проекта вместо всей папки;
- перенумеровывать историю после того, как работа по ней началась;
- заводить `US` вручную «с запасом»;
- давать истории плана номер из диапазона эталонов `US-9xxx`.
