# План, проект и ветка

## Найти план и проект

Планы лежат в **одном общем пространстве**, не по проектам:

```
~/.cursor/plans/<NNN>-*.md          глоб по номеру, три цифры с ведущими нулями
```

Проект берётся из frontmatter плана:

```yaml
project: имя-проекта          # как его называют в разговоре
base_branch: develop           # ветка, от которой идёт работа
status: draft | in-progress | merged
depends_on: [017]              # другие планы, которые должны быть закрыты
```

`depends_on` проверить до начала: если названный план не `merged`, сказать об
этом и спросить, а не выполнять вслепую.

**Рабочая копия проекта — та, что открыта в Cursor.** Если открыт другой
проект или папка вне проекта — сказать об этом и остановиться: правки в чужой
рабочей копии хуже, чем потерянный ход. Если имя в плане и открытый проект
расходятся по названию, но это очевидно он же (другая папка, тот же remote) —
назвать это вслух и продолжать.

Контекст проекта — его `AGENTS.md` или `README`: базовая ветка, команды
тестов, сборки и линта, особенности стека. Если базовая ветка неоднозначна —
спросить, не решать молча.

## Ветка

**Ворктри не создавать.** Лучше один тщательный план на несколько часов, чем
параллельные процессы, которые конфликтуют и жгут токены на порядок больше.
Работа идёт в основной рабочей копии проекта:

```bash
git checkout <base_branch>
git pull --ff-only
git checkout -b task/<slug>
```

Слаг задачи — короткий kebab-case по содержанию плана. Если ветка уже есть —
переиспользовать, не пересоздавать. Обновить frontmatter плана:
`status: in-progress`, `base_branch: <...>`, `branch: <...>`.

Прочитать `AGENTS.md` проекта явно (корневой плюс вложенные по необходимости).

## Проверка

- открытый в Cursor проект — тот, что назван в плане;
- `git branch --show-current` показывает ветку задачи, а не базовую;
- во frontmatter плана стоят `status: in-progress`, `branch` и `base_branch`;
- названные в `depends_on` планы закрыты — или человек сказал идти без них.

## Чего не делать

- работать в рабочей копии, которая не совпадает с проектом плана;
- заводить ворктри вместо работы в основной рабочей копии;
- начинать работу, не прочитав `AGENTS.md` проекта;
- выбирать базовую ветку молча, когда она неоднозначна.
