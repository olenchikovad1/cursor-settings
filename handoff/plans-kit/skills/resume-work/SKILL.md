# Продолжить с последнего места

Сценарий: чат закрылся, свет или сеть пропали, контекст сжали — работа
продолжается в новом чате. Пересказа беседы нет, есть только диск: коммиты и
журнал плана. По ним и восстанавливается состояние.

**Работу не начинать.** Задача скилла — доложить состояние и спросить.
Пользователь мог уйти с середины намеренно, и решение «что дальше» — его.

## 1. Найти незакрытые планы

```powershell
Select-String -Path ~/.cursor/plans/[0-9][0-9][0-9]-*.md -Pattern "^status: in-progress" -List | Select-Object -ExpandProperty Path
```

Для каждого — прочитать frontmatter (`project`, `branch`, `base_branch`) и
**хвост журнала**: последнюю запись `### <дата> · <ХОСТ>`.

Три вещи из журнала важнее всего:

- **Дальше** — что планировалось следующим шагом;
- **В работе на момент записи** — что было незакоммичено, когда всё
  прервалось. Именно это могло потеряться;
- **Грабли** — чтобы не наступить второй раз.

Открытые истории учёта — `calibrate.py stories --open`: история, открытая и не
закрытая, означает, что обрыв пришёлся на неё.

## 2. Сверить дерево проекта с планом

В рабочей копии проекта (той, что открыта в Cursor):

```bash
git branch --show-current
git fetch --quiet
git log --oneline <base_branch>..<branch>
git status --short
```

**`git branch --show-current` обязателен и идёт первым.** Ветка задачи живёт в
том же рабочем дереве, что и `base_branch`. Если рабочая копия осталась на
`develop`, а работа была в `task/...`, то сверка с планом покажет, что не
сделано ничего, — и это будет ложью. Не на той ветке — переключиться (или
сказать, если есть незакоммиченное, что мешает).

Затем сопоставить истории плана с коммитами ветки и назвать:

- какие истории закрыты (есть коммит и он делает то, что написано в истории);
- какие не отражены в коммитах вообще;
- что лежит незакоммиченным прямо сейчас (`git status`).

Сверять по существу, а не по названиям коммитов: сообщение «feat: US-0043» не
доказывает, что история сделана. Смотреть диффы тех коммитов, в которых
сомнение.

## 3. Доложить и спросить

Коротко, по форме:

```
План 014, проект склад, ветка task/picking.
Последняя запись журнала: 2026-09-02 · MY-PC.
Закрыто: US-0041, US-0042 (8 SP). Остаток 13 SP ≈ 45 мин.
Не отражено в коммитах: US-0043, US-0044.
Незакоммичено сейчас: правка списка позиций.
Открыта в учёте: US-0043 — закрыть с фактом или начать заново?
Продолжать с US-0043?
```

Оценку остатка — через `calibrate.py estimate --sp ... --compared-to ...` по
незакрытым историям, а не на глаз (см. `progress-time-estimates`).

## Если план не найден

Незакрытых планов нет — так и сказать, не выдумывать работу. Показать, что
менялось последним, чтобы пользователь сориентировался:

```bash
git log --oneline -10
```

## Проверка

- попросить продолжить в новом чате — приходит состояние: что закрыто, что
  в работе, чего нет в коммитах;
- сверить сказанное с деревом проекта — совпадает;
- посмотреть на последнюю строку ответа — это вопрос «продолжать с ...?», и
  `git status` после доклада показывает ровно то же, что до него.

## Чего не делать

- начинать работу до сверки состояния;
- полагаться на журнал, не глядя в дерево;
- считать незакоммиченное отсутствующим.

## Смежное

- `execute-plan` — собственно выполнение плана.
