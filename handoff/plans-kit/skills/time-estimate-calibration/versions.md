# Версии эталонов: граница объявляется, ничего не стирается

## Зачем

Смена модели, уровня усилий по умолчанию или приёма работы сдвигает время
шагов и историй разом. Пока журнал считался одним куском, тысячи старых
замеров топили сотни новых, и оценка говорила о работе, которой уже нет.
Стирать старое тоже нельзя: пока новых замеров мало, по ним нечего оценивать.

## Версии в этом наборе

`references/versions.json` приходит с двумя версиями:

| версия | с какого момента | что это |
|---|---|---|
| 1 | начало журнала | стартовый набор: замеры автора на Opus 5.5, сентябрь 2026 |
| 2 | 2026-10-01 | работа в Cursor — ваши замеры, с первого дня |

Версия 2 в поставке пуста: все ваши факты попадают в неё по времени записи.
Пока их мало, оценка идёт по версии 1 с пометкой «стар.»; с ростом числа
записей вес версии 2 растёт сам. Заводить третью версию ради «начали работать»
не нужно — для этого и есть вторая.

Своя версия нужна, когда у вас сменится что-то надолго: модель, уровень усилий
по умолчанию, приём работы.

## Как устроено

**Версию объявляет владелец:** дата начала и причина одной строкой, своими
словами.

```powershell
py -X utf8 ~/.cursor/time-analysis/calibrate.py versions
py -X utf8 ~/.cursor/time-analysis/calibrate.py version-new --from ГГГГ-ММ-ДД --reason "причина"
```

**Замер относится к версии по своему времени,** а не по полю в записи.
Поэтому граница с прошлой даты переносит уже снятые замеры без правки
журнала. Граница ставится на начало местного дня, замеры хранятся в UTC.

**В расчёт идут две последние версии,** текущая и предыдущая. Более старые
лежат в журнале и не читаются. Ни один факт не удаляется.

**Вес новой версии растёт плавно:** n/(n+5) по числу её замеров этого вида
(у шагов) или закрытых историй этой полки (у историй). Без порога «ещё нет /
уже есть»: на пороге оценка прыгала бы.

**Где новых данных нет, старое берётся с коэффициентом версии** — медианой
отношений «новое к старому» там, где данные есть в обеих. Вид, чьё отношение
выбивается из коридора, в коэффициент не входит: если весь сьют подорожал
втрое из-за смены проекта, размазывать это на соседей нельзя. Мало видов или
полок для коэффициента — отказ, старое идёт как есть.

**У каждого числа виден источник:** в памятке эталонов перед ходом стоит
«нов.», «нов. N%», «стар.×к» или «стар.»; в ответе `estimate` — блок
`version` и факт эталона с номером версии, в которой он снят.

**SP между версиями не меняются.** Размеры относительные: двигается цена
одного SP в минутах, а не расстановка эталонов по полкам. В полку новой
версии идут только истории, размер которых поставлен сравнением.

**Полки не убывают с ростом размера:** соседние нарушители сливаются в
среднее. Иначе одна длинная история делает 0.5 SP дороже 1 SP.

## Вопрос о новой версии

Детектор (`calibrate.py drift`) ищет **серию**, а не среднее: 15 закрытых
историй или 300 шагов подряд, медиана факт/оценка вне [0.7, 1.4], и почти все
по одну сторону. Считается против оценки, уже учитывающей смесь, и только по
записям после объявления текущей версии и после последнего «не сейчас».

Когда серия набрана, хук начала хода пишет об этом сессии. Сессия задаёт
вопрос карточкой с цифрами серии: «Завести версию» (причину пишет владелец)
или «Не сейчас». Ответ исполняется командой:

```powershell
py -X utf8 ~/.cursor/time-analysis/calibrate.py version-new --from ГГГГ-ММ-ДД --reason "причина владельца"
py -X utf8 ~/.cursor/time-analysis/calibrate.py version-decline
```

Версию заводит только ответ владельца, сама сессия её не заводит.

## Что поводом для версии не является

- **Разовое повышение уровня на отдельной задаче** — законная часть выборки.
- **Настроение одного дня.** Версия — граница на недели: новая набирает
  замеры с нуля. Колебания дня гасит плавный вес. Смена подхода, которая
  держится, — законная причина.

## Проверка

- `calibrate.py versions`: сумма замеров по версиям плюс записи без времени
  равна журналу;
- `calibrate.py estimate --sp N --compared-to US-9NNN` печатает блок `version`
  с долей новой версии и числом историй на полке;
- `calibrate.py drift` на живых данных называет момент, после которого
  копится серия.

Числа (5, 15, 300, коридоры) — предварительные и лежат в
`time-analysis/versions.py`, а не здесь.

## Чего не делать

- удалять или переписывать замеры старых версий;
- заводить версию без ответа владельца;
- возвращать множитель на режим поверх эталонов (см. [mode.md](mode.md)).

## Смежное
