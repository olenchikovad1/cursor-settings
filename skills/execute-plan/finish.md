# Завершение плана

## Порядок завершения

Реально прогнать тестовый сьют проекта (команды из манифеста или README) —
идти дальше только когда зелёные. Для доковой задачи — план выполнен
построчно.

Смёрджить ветку задачи в `base_branch`:

```bash
git checkout <base_branch>
git merge --no-ff <ветка задачи>
```

Тривиальный конфликт (форматирование, соседние строки) — разрешить самой,
сохранив полезные изменения обеих сторон. Смысловой конфликт (обе стороны
по-разному меняют одну логику) — `merge --abort`, объяснить и дождаться
решения пользователя, не придумывать его самой.

После мёрджа проверить, что ветка не разошлась:

```bash
git diff --exit-code <base_branch> <ветка задачи>
```

Пусто (`exit=0`) — можно убирать ветку задачи. Не пусто — не удалять
ничего, объяснить расхождение.

**Пуш `base_branch` на remote — обязательный шаг завершения.** Пока общая
ветка только локально ahead, план не выполнен: нет ни страховки на другой
машине, ни выкладки (где она завязана на remote). Детали и порядок уборки
веток — `process-git` / `branches.md` («Неотправленное — не сделано»,
«Слияние и уборка веток»). Ветка задачи к этому моменту уже должна быть на
remote (пуш после коммитов); после успешного пуша общей — удалить её
локально и на remote (`git branch -d`, `git push origin --delete …`).

Обновить frontmatter плана: `status: merged`, дописать в журнал итог —
только когда общая ветка уже на remote (или человек явно запретил пуш и
это в журнале).

Освободить заявку — план больше не в руках:

```bash
py -X utf8 ~/.cursor/hooks/plan_session.py --release <NNN>
```

Строго после того, как `status` перестал быть `in-progress`: хук сам замолкает
по статусу, но висящая заявка мешает следующей сессии взять этот план, если к
нему придётся вернуться.

## Если застряли

Не тянуть тихо и не перебирать попытки в одиночку — сказать пользователю
прямо, что не получается и почему.

Это про **настоящий тупик**, а не про паузу после каждой истории: если работу
можно продолжить, приняв разумное допущение, она продолжается, а вопрос уходит
в файл открытых вопросов (см. раздел 0).

## Проверка

- `git diff --exit-code <base_branch> <ветка задачи>` пусто — только тогда
  ветка удаляется;
- `git status` по `base_branch` не показывает ahead относительно origin
  (пуш сделан);
- во frontmatter плана `status: merged` и итоговая запись в журнале;
- `plan_session.py --status` больше не показывает этот план заявленным;
- ветка задачи снята и локально, и на remote (если не оставлена по явной
  причине в журнале).

## Чего не делать

- удалять ветку, не убедившись, что слияние прошло полностью;
- объявлять план выполненным при локальном merge без пуша общей ветки;
- разрешать смысловой конфликт слияния за человека;
- снимать заявку до того, как статус перестал быть `in-progress`;
- тянуть тупик молча вместо того, чтобы сказать о нём.
