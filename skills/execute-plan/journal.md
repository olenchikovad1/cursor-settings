# Журнал плана

## Запись после каждого смыслового блока

В конец файла плана, после каждого смыслового блока (не после каждого
коммита, но и не один раз в самом конце):

```markdown
## Журнал

### 2026-09-02 18:04 · RBB-0001
US-0042 закрыта, коммит `a3f21c9`. Демонстрация проведена: паллета в 60
позиций пройдена без мыши, чужой штрихкод прогресс не сбросил.
**В работе на момент записи:** US-0043, правка `alembic/versions/0028_*.py`, не закоммичена.
**Дальше:** перенумерование 0028 в 0031.
**Грабли:** `ozon.py:44` вызывает `get_mp_connection` в один аргумент.
```

Ссылаться на истории по номеру `US-NNNN` — по нему запись сопоставляется с
учётом времени.

Хост — `$COMPUTERNAME`. Секция «В работе на момент записи» не декоративная:
WIP-снапшотов в схеме нет сознательно, и незакоммиченная работа при обрыве
света остаётся только на диске той машины. На второй машине понять, что
именно потерялось, можно **только** по этой строке. Нет её — нет и способа
продолжить с того же места.

Журнал уезжает в git сам: `~/.claude` коммитится и пушится хуком на каждом
ходу.

## Проверка

- после каждого смыслового блока найти запись в журнале — есть, с номером
  истории;
- открыть последнюю запись на другой машине — по ней понятно, что было в
  работе и что потерялось;
- сверить номера историй в журнале с планом — совпадают.

## Чего не делать

- писать журнал один раз в конце плана;
- опускать строку «В работе на момент записи»;
- пересказывать в журнале боль истории вместо ссылки на её номер.

## Смежное

- `resume-work` — как эта запись читается на второй машине.
- [story.md](story.md) — что должно быть сделано до записи.
