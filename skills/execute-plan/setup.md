# План, проект и ветка

## Найти план и проект

Планы лежат в **одном общем пространстве**, не по проектам:

```
~/.claude/plans/<NNN>-*.md          глоб по номеру, три цифры с ведущими нулями
```

Файлы без числового префикса (`luminous-jumping-goblet.md` и подобные) — это
выгрузки plan-mode самого Claude Code, к нумерованным планам они не
относятся и в глоб не попадают.

Проект берётся из frontmatter плана:

```yaml
project: assemblage-point      # ключ в реестре, НЕ путь
base_branch: develop           # если задан — приоритетнее манифеста
status: draft | in-progress | merged
depends_on: [017]              # другие планы, которые должны быть закрыты
```

`depends_on` проверить до начала: если названный план не `done`, сказать об
этом и спросить, а не выполнять вслепую.

Планы с номера 021 написаны как последовательность пользовательских историй
(см. `write-plan`). Планы 001–020 — в старом формате, списком шагов; для них
всё ниже про истории просто не применяется.

Путь к проекту **вычислять нельзя** — он разный на домашней и офисной машине
(`D:/Проекты/Laretto/assemblage-point` против `C:/Projects/assemblage-point`).
Только через резолвер:

```bash
py ~/.claude/hooks/resolve_project.py <name> --json
```

Отдаёт `path`, `branch`, `remote`, `base_branch`, `branch_prefix`. Коды
возврата: 0 — нашлось, 2 — не нашлось, 3 — несколько клонов. На 2 и 3
**спросить пользователя**, а не угадывать: он скажет путь, резолвер запомнит
его через `--register`.

Контекст проекта — `~/.claude/projects.d/<name>.md`: базовая ветка, префикс
ветки, команды тестов/сборки/линта, особенности стека. Если манифеста нет
(проект новый) — вывести конвенции из README/CLAUDE.md проекта, а при
неоднозначности (какая ветка базовая) спросить, не решать молча. Заодно
создать манифест, чтобы в следующий раз не выводить заново.

## Ветка

**Ворктри не создавать.** Решение пользователя: лучше один тщательный план на
несколько часов, чем параллельные процессы, которые конфликтуют и жгут токены
на порядок больше. Работа идёт в основной рабочей копии проекта:

```bash
git checkout <base_branch>
git pull --ff-only
git checkout -b <branch_prefix><slug>
```

Слаг задачи — короткий kebab-case по содержанию плана. Если ветка уже есть —
переиспользовать, не пересоздавать. Обновить frontmatter плана:
`status: in-progress`, `base_branch: <...>`, `branch: <...>`.

Прочитать релевантные `CLAUDE.md` проекта явно (корневой плюс `backend/` и
`web/` по необходимости).

## Проверка

- `resolve_project.py <имя> --json` отвечает кодом 0 и путём, который
  существует на этой машине;
- `git branch --show-current` показывает ветку задачи, а не базовую;
- во frontmatter плана стоят `status: in-progress`, `branch` и `base_branch`;
- названные в `depends_on` планы закрыты — или человек сказал идти без них.

## Чего не делать

- вычислять путь к проекту вместо обращения к резолверу;
- заводить ворктри вместо работы в основной рабочей копии;
- начинать работу, не прочитав `CLAUDE.md` проекта;
- выбирать базовую ветку молча, когда она неоднозначна.
