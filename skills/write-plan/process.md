# Как ведётся работа над планом

## Вопросы задаются здесь, а не при выполнении

Этап плана — единственное место, где уточнения дёшевы. Всё, что непонятно про
предметную область, границы задачи и выбор подхода, выясняется **до** того, как
план уйдёт в работу.

Причина простая: выполнение идёт целиком, без остановок (см. `execute-plan`),
и вопрос, всплывший в середине, стоит человеку простоя до его следующего
сообщения. Поэтому лучше задать три вопроса сейчас, чем один потом.

## Порядок работы

1. Выслушать задачу целиком, не начиная планировать по ходу.
2. Разобраться в предметной области настолько, чтобы написать боль от лица
   конкретного актора. Не хватает знания — **спросить**, а не выдумать.
3. Разбить на истории по логическим единицам пользы, не по этапам работы.
   «Модель», «миграция», «фронт» — это этапы, а не истории.
4. Проставить SP сравнением с эталонами.
5. Прогнать валидатор:
   ```bash
   py -X utf8 ~/.claude/hooks/lint_plan.py ~/.claude/plans/NNN-*.md
   ```
6. Показать пользователю итог: сколько историй, суммарные SP и минуты.

## Проверка

- посмотреть, все ли вопросы заданы до запуска плана, — при выполнении
  вопросов не осталось;
- прогнать валидатор — чисто;
- сверить разбиение с планом: истории названы по единицам пользы, а не по
  этапам работы («модель», «миграция», «фронт» — этапы).

## Чего не делать

- планировать по ходу рассказа, не дослушав задачу;
- откладывать уточнения на этап выполнения;
- разбивать план по этапам работы вместо единиц пользы.
