# Нумерация планов и историй

## Нумерация

### Номер плана

`NNN` в имени файла — сквозной **через всю папку планов, а не через планы
этого проекта**. Следующий номер: максимальный `NNN` в `~/.cursor/plans/`
и в `~/.claude/plans/` (второй только читается). Новый файл — в `~/.cursor/plans/`.
плюс один, независимо от того, к какому проекту относится предыдущий.

Это сказано отдельно, потому что уже нарушалось: два плана получили номер
026 — один по проекту `assemblage-point`, второй по `resume`. Номер второму
выбрали, посмотрев на планы своего проекта (024, 025) и прибавив один. Файл
чужого плана при этом лежал рядом и был закоммичен — то есть дело не в
рассинхронизации между машинами, а в том, что смотрели не на папку.

Проверка одной командой перед созданием файла:

```bash
ls -1 ~/.claude/plans/ | grep -oE '^[0-9]{3}' | sort -n | tail -1
```

### Направление в имени файла

Имя плана — `NNN-<направление>-<слаг>.md`. Направление стоит и полем `epic:`
во frontmatter; это одно и то же, слово «эпик» в тексте историй не
используется намеренно, чтобы не смешивать с чужими трактовками.

Направление задаётся **смыслом, а не репозиторием**: подключение портала к
платформе — работа по платформе, хотя правки лежат в портале.

**В одном плане одно направление.** Работа, надиктованная сразу по двум,
разъезжается на два плана, и об этом говорится вслух при сдаче — иначе
смешанный план невозможно ни оценить, ни закрыть целиком. Ровно это уже
случилось: подключение портала и калибровка времени попали в один план, хотя
идейно относятся к разному.

**Повтор номера законен только у закрытых планов разных направлений** — там
номер фиксирует момент в хронологии, а не файл. У планов, по которым работа
идёт или ещё пойдёт, номер уникален: владением, паузой и маркером сессии
управляют по голому номеру, и два живых плана с одним номером означают, что
пауза на одном глушит другой. Повтор внутри одного направления — ошибка
всегда, и правится он до начала работы.

Проверяет это `hooks/lint_plan.py`: имя без направления — ошибка с плана 039,
замечание для 021–038, для 001–020 не проверяется вовсе.

### Номер истории

`US-NNNN`, четыре цифры, сквозная через все планы. Следующий номер берётся из
**последнего по номеру плана** — того самого, который нашла команда выше:
максимальный `US-NNNN` в нём плюс один. Все планы сканировать не нужно.

Столкновение здесь дороже, чем кажется: эталонные истории лежат файлами
`references/stories/US-NNNN.md`, и два разных `US-0064` попадут в один файл.
Поэтому «последний по номеру план» — именно последний в папке, а не последний
свой.

Если номера совпали на двух машинах без сети — это исправляется
перенумерованием до начала работы, пока замена стоит одну команду.
После начала работы номер уже лежит в журнале фактов, и трогать его дороже:
тогда живут оба, а различать истории помогают заголовок и боль рядом
с номером.

Планы 001–020 написаны в старом формате и не мигрируются.

## Проверка

- перед созданием файла выполнить команду поиска максимального номера — файл
  назван следующим за ним;
- найти в папке два плана с одним номером — таких нет;
- открыть последний по номеру план и сверить максимальный `US-NNNN` с новым —
  не пересекаются.

## Чего не делать

- выбирать номер плана, глядя на планы своего проекта вместо всей папки;
- перенумеровывать историю после того, как работа по ней началась;
- заводить `US` вручную «с запасом».
