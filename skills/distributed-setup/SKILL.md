# Распределённая инфраструктура `~/.claude`

Репозиторий Claude (`~/.claude`) отсюда не коммитится и его автосинк не
запускается. Настройки Cursor едут своим репозиторием — [cursor-sync.md](cursor-sync.md).

Два пространства:

- **обсуждение** — `~/.claude`, один приватный репозиторий: планы, журналы,
  реестр проектов, скиллы, калибровка, хуки. Синхронизируется между машинами;
- **реализация** — рабочие репозитории проектов, лежащие на каждой машине по
  своему пути.

Работа единовременно идёт только на одной машине. Параллельных сессий не
бывает — это условие задачи, а не допущение.

## Раскладка

```
plans/NNN-*.md              планы, сквозная нумерация по ВСЕМ проектам
projects.d/<name>.md        манифест проекта: remote, ветки, команды тестов
memory/<name>/*.md          память проектов, ключ — имя проекта
local.json                  МАШИННОЕ, в .gitignore: host, role, roots, cache
local.example.json          образец local.json, ОТСЛЕЖИВАЕТСЯ
infra_ssh_hosts.md          СЕКРЕТ, в .gitignore, приносится на флешке
hooks/                      резолвер, синк, автосинк, хуки оценок
logs/                       МАШИННОЕ: что делал автосинк, вывод push
time-analysis/              журнал калибровки, НЕ в основной ветке
ветка transcripts           orphan, окно 7 дней, ОДИН пересобираемый коммит
ветка calibration           обычная, с историей, замеры времени
ветка wip/<роль>            личная страховка машины, пересобирается force
```

## Правила

Каждый пункт действует сам по себе. За причиной, примерами и проверкой
открывается лист.

### Пути к проектам → [resolver.md](resolver.md)

- **Путь к проекту вычислять нельзя** — он разный на домашней и офисной
  машине. Только через резолвер.
- **Проект адресуется именем из реестра, а не путём.**
- **Не нашлось или нашлось несколько — спросить человека,** а не угадывать;
  ответ запоминается через `--register`.

### Синк состояния → [sync.md](sync.md)

- **`SessionStart` подтягивает `~/.claude` и раскладывает транскрипты с
  памятью.**
- **Прежде чем делать выводы, проверить, что синк отработал:** иначе всё
  читается из устаревших файлов.
- **Машинное не отслеживается:** `local.json`, логи, кэш.

### Автокоммит и автопуш → [autocommit.md](autocommit.md)

- **`~/.claude` коммитится и пушится сам, на каждом ходу.** Проектные
  репозитории — нет.
- **Автопуш включается флагом в манифесте,** и только у своего репозитория.
- **Расхождение историй чинится разбором, а не силовым пушем.**
- **Следы приватной сессии** (file-history, транскрипт) — команды для второй
  машины после переписывания 29.09.2026 — в листе, раздел «Приватные проекты».

### Личные и боковые ветки → [branches.md](branches.md)

- **У каждой машины своя роль и своя `wip/<роль>`.** Одинаковая роль на двух
  машинах возвращает ровно ту поломку, ради которой схема и заведена.
- **Чужая `wip` автоматически не сливается:** что делать с брошенной на
  полпути работой, решает человек.
- **Транскрипты — orphan-ветка с окном в семь дней,** калибровка — обычная
  ветка с историей.

### Кто ведёт план → [plan-ownership.md](plan-ownership.md)

- **План ведёт ровно одна сессия — та, которая его заявила.**
- **Stop-хук требует продолжения только от неё;** остальным он молчит.
- **Блокировка хука — не задание.** Держит ход в чужой сессии — это баг, о
  котором надо сказать человеку, а не идти работать в чужую рабочую копию.

### Диагностика → [diagnostics.md](diagnostics.md)

- **Сначала логи автосинка и push, потом гипотезы.**
- **Часть состояния не лежит нигде по устройству схемы** — искать его
  бесполезно, и список такого приведён.

## Смежное

- `execute-plan` — работа по плану, которую этот механизм подпирает.
- `resume-work` — восстановление состояния после переезда между машинами.
- `time-estimate-calibration` — что лежит в ветке калибровки.
- `transfer-project-skills` — где живёт библиотека правил и как она уезжает в
  проекты.
