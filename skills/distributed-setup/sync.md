# Синк состояния между машинами

## Синк состояния

```bash
py -X utf8 ~/.claude/hooks/sync_state.py --status
py -X utf8 ~/.claude/hooks/sync_state.py --in      # разложить пришедшее
py -X utf8 ~/.claude/hooks/sync_state.py --out     # собрать и выложить
```

`--in` висит на `SessionStart` (через `autosync_claude.py`), `--out` — на
`SessionEnd`.

### Почему под именем проекта, а не как есть

И транскрипты, и память Claude Code держит в `projects/<слаг-от-пути>/`.
Слаг — это путь, у которого **каждый символ кроме букв, цифр и точки заменён
на дефис**:

```
C:/Projects/assemblage-point        -> C--Projects-assemblage-point
C:/Users/User/.claude               -> C--Users-User-.claude
D:/Проекты/Laretto/assemblage-point -> D----------Laretto-assemblage-point
```

Третий пример и раскрыл правило: десять дефисов — это двоеточие, слеш, семь
букв «Проекты» и слеш. Пока не появилась папка кириллического пути, правило
выглядело как «разделители в дефисы», и это было неверно.

Раз слаг зависит от пути, на двух машинах он разный, и синхронизировать папки
как есть бессмысленно: на второй машине они окажутся чужими и `--resume`
сессию не увидит. Поэтому в git всё лежит под именем проекта, а скрипт
раскладывает по локальному слагу.

Скрипт собирает данные из **всех** папок проекта, а не только из своей.
Память, записанная в офисе, лежит под офисным слагом, и брать только свой
означало бы её потерять.

### Почему `--resume` вообще работает

Индекса сессий у Claude Code нет: в `~/.claude.json` по проектам лежат только
настройки (`allowedTools`, `hasTrustDialogAccepted`), а `--resume` сканирует
`*.jsonl` в папке слага. Значит положенный в папку файл появляется в списке
сессий сам.

### Почему транскрипты на orphan-ветке

`git rm` не уменьшает репозиторий: блобы остаются в истории навсегда. Файлы
сессий весят 8–14 МБ, и при обычных коммитах каждый ход одна сессия дала бы
порядка 400 МБ объектов.

Ветка `transcripts` пересобирается целиком **одним** коммитом
(`hash-object` → `update-index` в отдельный индекс → `write-tree` →
`commit-tree` без родителя → `update-ref` → `push --force`). Размер
репозитория при этом равен текущему окну и не растёт: проверено тремя
циклами сборки — 7.28 МБ до и после.

Плумбинг, а не ворктри: рабочее дерево не трогается вообще.

Ветка служебная, ей владеет только этот скрипт — force-push там безопасен.
**В обычные ветки force-push не делать никогда** — кроме одного явно
разрешённого случая, описанного ниже в «Катящемся коммите»: `master` самого
`~/.claude`, по флагу `rolling_commits` в манифесте. Больше нигде.

Окно и его учёт — в `index.json` внутри ветки: `{файл: mtime}`. Без него
нельзя понять возраст файла, пришедшего с другой машины: в имени сессии
(UUID) даты нет.

## Проверка

- на второй машине выполнить восстановление состояния — план, журнал и память
  те же, что на первой;
- `autosync_claude.py --status` и `sync_state.py --status` — «не подтянуто»
  ноль;
- открыть память проекта на обеих машинах — содержимое совпадает.

## Чего не делать

- править хуки, не прочитав, как устроен автосинк;
- считать, что пул прошёл, не посмотрев на статус;
- держать машинные файлы (`local.json`, логи) в отслеживаемых.
