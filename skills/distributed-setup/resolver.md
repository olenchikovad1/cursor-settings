# Разрешение путей к проектам

## Разрешение путей: имя проекта, а не путь

Планы ссылаются на проект по **имени**. Путь у каждой машины свой:

| Машина | Путь |
|---|---|
| `DESKTOP-FA9EUCC` (дом) | `D:/Проекты/Laretto/assemblage-point` |
| офис | `C:/Projects/assemblage-point` |

```bash
py ~/.claude/hooks/resolve_project.py <name> --json    # путь и контекст
py ~/.claude/hooks/resolve_project.py --list           # все проекты и состояние
py ~/.claude/hooks/resolve_project.py --rescan         # сбросить кэш, обойти корни
py ~/.claude/hooks/resolve_project.py --register <name> <path>
```

Порядок: `path_expr` из манифеста (для машинно-независимых путей вроде
`~/.claude`) → кэш `local.json` → обход `roots` с поиском репозитория, чей
`git remote get-url origin` совпадает с `remote` манифеста. Полный скан
корней — около секунды.

Коды: 0 нашлось, 2 не нашлось, 3 несколько клонов. На 2 и 3 — **спросить
пользователя**, не угадывать.

Репозиторием считается каталог с `.git` **как каталогом**. У ворктри `.git` —
файл-ссылка, а `origin` тот же, и без этой проверки резолвер вернул бы
ворктри вместо корня проекта.

### Добавить новый проект

1. Создать `projects.d/<name>.md` с frontmatter: `name`, `remote`,
   `default_base_branch`, `branch_prefix`, команды тестов/сборки/линта. Тело —
   стек и особенности. Файл уезжает в git, на второй машине появится сам.
2. Убедиться, что репозиторий лежит под одним из `roots` в `local.json`.
   Если нет — либо добавить корень, либо `--register`.
3. Проверить: `resolve_project.py <name> --json`.

### Добавить машину

1. Клонировать репозиторий в `~/.claude`.
2. Завести `local.json` **скриптом**, не руками:

   ```bash
   py -X utf8 ~/.claude/hooks/machine.py --init home --roots D:/Проекты
   py -X utf8 ~/.claude/hooks/machine.py --status
   ```

   Скрипт проверит роль, не затрёт уже накопленный `cache` и дополнит
   `roots`, а не заменит их. Схема полей — в `local.example.json`, он
   отслеживается и приезжает с репозиторием ровно ради этого шага.
3. Принести `infra_ssh_hosts.md` руками (в git его нет и не будет).
4. Проверить `resolve_project.py --list` и `sync_state.py --status`.

Пока роль не задана, `SessionStart` говорит об этом вслух на каждой сессии, а
автосинк работает по-старому — пушит прямо в `master`. Это рабочий режим, но
он и есть источник расходящихся историй, ради которого заведены личные ветки.

## Проверка

- разрешить путь проекта резолвером на обеих машинах — обе отвечают кодом 0 и
  существующим путём;
- назвать проект, которого нет в реестре, — резолвер возвращает 2, а не
  угаданный путь;
- проверить, что в скиллах и планах нет ни одного зашитого абсолютного пути.

## Чего не делать

- вычислять путь к проекту вместо обращения к резолверу;
- регистрировать клон, не спросив человека, какой из нескольких настоящий;
- держать пути в скилле вместо реестра.

## Смежное

- [sync.md](sync.md) — почему реестр одинаков на обеих машинах.
- `execute-plan` — где резолвер вызывается по ходу работы.
